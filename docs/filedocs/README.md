## The five facts the whole project turns on

If you remember nothing else before the viva, remember these. Each one is the subject of
at least one question, and each is demonstrated by a passing test.

1. **You cannot `COMMIT` inside a PL/pgSQL block that has an `EXCEPTION` handler.**
   That block is an internal subtransaction and transaction control is illegal inside one.
   → [sql_04](sql_04_stored_procedures.md)

2. **A row-level trigger fires once per affected row, even for one set-based statement.**
   This is how 150,232 ledger rows are generated by three `UPDATE`s, and why `COPY` (an
   `INSERT` path) produces none at all. → [postgres_seeder](postgres_seeder.md)

3. **`$facet` sub-pipelines cannot use indexes.** Only the stage immediately preceding
   `$facet` can. Measured cost of getting this wrong: 909× the documents examined.
   → [mongo_03](mongo_03_workflow4_facet.md)

4. **`RANGE` fixes the window boundary; only the gap fill fixes the denominator.**
   Neither frame type invents a row for a day with no orders.
   → [sql_06](sql_06_window_analytics.md)

5. **`REFRESH MATERIALIZED VIEW CONCURRENTLY` needs a non-partial `UNIQUE` index on the
   view, and the view must already be populated.** → [sql_05](sql_05_materialized_views.md)
